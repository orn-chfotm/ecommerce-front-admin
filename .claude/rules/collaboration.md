# 협업

## 언어

- 설명은 한국어로 한다.
- 기존 파일이 명확히 한국어를 사용하지 않는 한 코드, 식별자, 주석, 커밋 메시지, 명령어 이름은 영어로 작성한다.

## 수정 전

- 가정을 명시한다.
- 여러 해석이 가능하면 임의로 하나를 선택하지 않고 가능한 해석을 제시한다.
- 요청이 불명확해서 구현 방향이 틀어질 수 있으면 멈추고 질문한다.
- 요청을 만족하는 가장 단순한 구현을 우선한다.

## 파일 접근

- 사용자가 언급한 파일을 먼저 읽는다.
- 추가 확인이 필요하면 해당 파일이 직접 참조하는 관련 파일부터 읽는다.
- 작업과 직접 관련 없는 파일을 읽어야 하면 이유와 대상을 먼저 설명한다.

## 구현

- 작업에 필요하지 않으면 인접 코드를 리팩터링하지 않는다.
- 다른 스타일이 더 깔끔해 보여도 기존 스타일을 따른다.
- 변경한 모든 줄은 사용자 요청을 수행하는 데 필요해야 한다.

## 리뷰 및 보고

- 선택에 따른 장단점과 불확실성을 명시한다.
- 실패한 명령이나 부분 검증 상태를 숨기지 않는다.
- 최종 보고에는 변경 파일과 검증 결과를 포함한다.

## [금지사항]

- 추측성 기능을 추가하지 않는다.
- 요청하지 않은 추상화, 설정 옵션, 확장 포인트를 만들지 않는다.
- 발생할 수 없는 시나리오에 대한 에러 처리를 작성하지 않는다.
- 사용자 요청과 무관한 기존 미사용 코드, 주석, 포맷을 정리하지 않는다. 발견하면 언급만 한다.
- 매 작업마다 저장소 전체를 탐색하지 않는다.
- 실패한 테스트, 빌드, lint 결과를 요약에서 빼거나 완화해서 표현하지 않는다.
