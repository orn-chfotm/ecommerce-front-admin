# 작업 절차

이 프로젝트는 PM → CTO → PL → PA 역할 모델을 **작업 규모별로 축약 적용**한다.

원본 기준은 `.ai-prompts` starter 문서지만, 이 프로젝트는 그 문서를 직접 로드하지 않는다. 이 파일이 단일 기준이다.

## 역할과 agent

각 역할은 `.claude/agents/`의 subagent로 연결되어 있다.

| 역할 | agent | 도구 | 책임 |
|---|---|---|---|
| PM | `pm` | 읽기 전용 | 목표, 범위, 비범위, 산출물, 승인 지점 |
| CTO | `cto` | 읽기 + 검증 실행 | 기술 적합성, 리스크, 대안, 제한성 |
| PL | `pl` | 읽기 + 검증 실행 | 작업 경계, 재사용 전략, 검증 기준, PA 코드 1차 리뷰 |
| PA | `pa` | 읽기/쓰기 | 승인된 작업 단위 실행 |
| 전문 리뷰 | `frontend-reviewer` | 읽기 + 검증 실행 | FSD 의존 방향, Next.js 동작 정밀 검사 |

`pl`과 `frontend-reviewer`의 경계: `pl`은 작업 경계·재사용·통합 관점으로 리뷰하고, 레이어 의존 방향이나 server/client 경계를 정밀하게 확인해야 할 때 `frontend-reviewer`를 호출한다.

사용자는 최종 승인자이며, 어떤 agent도 스스로 승인할 수 없다.

## 규모별 적용

| 작업 유형 | 호출할 agent | 승인 게이트 |
|---|---|---|
| 문구, 스타일, 단일 파일 수정 | 없음. 직접 실행 | 없음. 결과 보고만 |
| 한 레이어 안의 컴포넌트/기능 추가 | `pl` → `pa` | 없음. 결과 보고만 |
| 여러 FSD 레이어에 걸친 변경 | `pm` → `pl` → `pa` | 실행 전 1회 |
| 라우팅, 레이아웃, server/client 경계, config 변경 | `pm` → `cto` → `pl` → `pa` | 실행 전 1회 |
| 의존성 추가, `tsconfig` 변경, 디렉토리 구조 변경, 아키텍처 변경 | `pm` → `cto` → `pl` → `pa` | 실행 전 필수. 생략 불가 |

## 단계 전환 규칙

- 한 역할의 산출물이 나오면 **멈추고 사용자 확인을 받은 뒤** 다음 역할로 넘어간다.
- 위 표에서 "승인 게이트 없음"인 작업만 연속 진행할 수 있다.
- PL은 구현 수립 중 기술 문제를 발견하면 PM을 거치지 않고 `cto`를 직접 호출할 수 있다. 이때도 사용자 확인을 먼저 받는다.
- PA는 `cto`를 직접 호출하지 않는다. `pl`을 통해 에스컬레이션한다.

## 승인이 반드시 필요한 항목

- 신규 의존성 추가
- `tsconfig.json`, `next.config.ts`, `eslint.config.mjs`, `package.json` 변경
- 디렉토리 구조 변경
- 인증, 권한, 배포 방식 변경
- FSD 의존 방향 예외 허용
- 승인된 작업 범위 밖 파일 수정
- 계획에 없던 새 파일 추가

## 승인 요청 형식

```md
## [역할명] 승인 요청

**현재 단계**: (PM / CTO / PL / PA)
**다음 단계**: (전달받을 역할 또는 완료)
**요약**: (핵심 내용 1~3줄)

- 결정할 내용:
- 추천 방향:
- 대안:
- 리스크:
- 승인 후 실행할 작업:

승인 / 거부 / 보류 / 재요청
```

## 에스컬레이션 형식

```md
## [역할명] 에스컬레이션 요청

**요청 역할**: (PL / PA)
**대상 역할**: (CTO / PL / PM)
**요청 이유**: (기술 리스크 / blocker / 범위 이탈)
**질문 또는 요청 내용**:

승인 / 거부 / 보류 / 재요청
```

## 완료 보고 형식

```md
## 완료 보고

- 완료한 작업:
- 변경된 파일:
- 검증 결과: (lint / build)
- 에러/불가 처리:
- 남은 이슈:
```

## 반려와 되돌림

거부 또는 재요청이 발생하면 **반려된 단계의 역할이** 새 안을 다시 낸다.

| 상황 | 되돌릴 단계 |
|---|---|
| 실행 중 승인되지 않은 구조 변경이 필요해짐 | PL |
| 기술 방향이 바뀜 | CTO |
| 작업 범위가 바뀜 | PM |
| 사용자 승인 조건이 바뀜 | 승인 요청 재작성 |

PA는 반려 시 직접 재구현하지 않고 PL의 새 지시를 기다린다.

## [금지사항]

- 위 표에서 승인 게이트가 있는 작업을, 사용자 승인 전에 파일 생성/수정하거나 상태를 변경하는 명령을 실행하지 않는다.
- "승인이 반드시 필요한 항목"을 작업 규모가 작다는 이유로 생략하지 않는다.
- 한 역할의 산출물을 낸 직후 사용자 확인 없이 다음 역할 산출물을 이어서 작성하지 않는다.
- 에스컬레이션 요청과 그 응답을 사용자 확인 없이 연속으로 작성하지 않는다.
- 한 번 받은 승인을 범위 밖 변경까지 확대 해석하지 않는다.
- AI의 자체 검토 결과를 사용자 승인으로 대체하지 않는다.
- 계획 수립용 read-only 탐색을 넘어, 승인 전에 `npm install`, `npm run build`, 배포처럼 상태를 바꾸는 명령을 실행하지 않는다.
